# MongoDB Production Service

Private-first authenticated MongoDB replica-set service for the VSM host.

## Architecture

```text
Platform Admin / n8n / n8n-worker
          |
       mongo_net
          |
   platform-mongodb
          |
        rs0
          |
       /data/db
```

The initial deployment does not publish `27017` to the host. Same-VPS clients use:

```text
mongodb:27017
```

MongoDB is configured as a single-node replica set from day one so transactions and change streams are available and later replica-set expansion does not require migration from standalone mode.

## Runtime layout

```text
/srv/infrastructure/databases/mongodb/
├── compose.yml
├── .env
├── config/mongod.conf
├── data/
├── backups/
├── scripts/init-replica.sh
└── secrets/
    ├── root_password
    ├── controller_password
    └── replica_keyfile
```

Create runtime state:

```bash
cd /srv/infrastructure/databases/mongodb
mkdir -p data backups secrets
cp .env.example .env
chmod 600 .env
openssl rand -hex 32 > secrets/root_password
openssl rand -hex 32 > secrets/controller_password
openssl rand -hex 64 > secrets/replica_keyfile
sudo chown root:root secrets/root_password
sudo chmod 600 secrets/root_password
sudo chown 1001:1001 secrets/controller_password
sudo chmod 600 secrets/controller_password
sudo chmod 400 secrets/replica_keyfile

docker network inspect mongo_net >/dev/null 2>&1 || docker network create mongo_net
```

`controller_password` is owned by UID/GID 1001 because Platform Admin runs as UID/GID 1001 and mounts that file read-only. Root and replica-keyfile secrets are not mounted into Platform Admin.

The official Mongo image normally runs the database process as UID/GID 999. Verify on a new major image before applying ownership:

```bash
sudo chown -R 999:999 data
sudo chown 999:999 secrets/replica_keyfile
```

Start:

```bash
docker compose config
docker compose pull
docker compose up -d
docker compose ps
docker logs platform-mongodb --tail 100
docker logs platform-mongodb-init --tail 100
```

The one-shot initializer creates `rs0` with member `mongodb:27017` and creates/rotates the `platform_controller` account.

## Platform Admin

Platform Admin mounts only the controller password and connects privately to:

```text
mongodb://platform_controller:...@mongodb:27017/admin?authSource=admin&replicaSet=rs0
```

The root credential remains outside Platform Admin.

The `/mongodb` manager supports managed database + user creation, password rotation, encrypted connection reveal, database/user deletion and database size reporting.

Application users receive `readWrite` only on their own managed database.

## n8n

Attach both main and worker to `mongo_net`. MongoDB nodes should use host `mongodb`, port `27017`, replica set `rs0`, and the application-specific credential generated by Platform Admin.

## Backup and restore

Use a temporary MongoDB client container on `mongo_net` or `docker exec` without exposing port 27017.

Example archive backup:

```bash
mongodump --uri='mongodb://USER:PASSWORD@mongodb:27017/DATABASE?authSource=DATABASE&replicaSet=rs0' --archive=backup.archive --gzip
```

Restore:

```bash
mongorestore --uri='mongodb://USER:PASSWORD@mongodb:27017/DATABASE?authSource=DATABASE&replicaSet=rs0' --archive=backup.archive --gzip
```

Perform an actual restore test before treating a backup workflow as production-ready.

## Security invariants

```text
27017 is not host-published.
authorization is enabled.
replica-set internal authentication uses a persistent keyfile.
root is bootstrap/emergency only.
platform_controller is management-only.
application users are scoped to their own database.
root/controller/keyfile secrets never enter Git.
Platform Admin stores generated app passwords encrypted in its credential vault.
```
