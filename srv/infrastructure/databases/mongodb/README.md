# MongoDB Production Service

Private-first authenticated MongoDB replica-set service for the VSM host.

## Architecture

```text
Platform Admin / n8n / n8n-worker
          |
       mongo_net
          |
   platform-mongodb
          |
        rs0
          |
       /data/db
```

Port `27017` is not host-published. Same-VPS clients use `mongodb:27017`.

MongoDB is configured as a single-node replica set from day one so transactions and change streams are available and later replica-set expansion does not require migration from standalone mode.

## Runtime layout

```text
/srv/infrastructure/databases/mongodb/
├── compose.yml
├── .env
├── config/mongod.conf
├── data/
├── backups/
├── scripts/init-replica.sh
└── secrets/
    ├── root_password
    ├── controller_password
    └── replica_keyfile
```

## First deployment

```bash
cd /srv/infrastructure/databases/mongodb
mkdir -p data backups secrets
[ -f .env ] || cp .env.example .env
chmod 600 .env

[ -f secrets/root_password ] || openssl rand -hex 32 > secrets/root_password
[ -f secrets/controller_password ] || openssl rand -hex 32 > secrets/controller_password
[ -f secrets/replica_keyfile ] || openssl rand -hex 64 > secrets/replica_keyfile

docker network inspect mongo_net >/dev/null 2>&1 || docker network create mongo_net
```

The official Mongo image normally runs the database process as UID/GID `999`; verify this when changing image families. The root password and replica keyfile must be readable by the MongoDB process, while the controller password only needs to be readable by the root-run bootstrap sidecar:

```bash
sudo chown 999:999 secrets/root_password secrets/replica_keyfile
sudo chmod 600 secrets/root_password
sudo chmod 400 secrets/replica_keyfile
sudo chown root:root secrets/controller_password
sudo chmod 600 secrets/controller_password
sudo chown -R 999:999 data
```

Start:

```bash
docker compose config
docker compose pull
docker compose up -d
docker compose ps
docker logs platform-mongodb --tail 100
docker logs platform-mongodb-init --tail 100
```

The one-shot `platform-mongodb-init` container initiates `rs0` when necessary, waits until the node is writable PRIMARY, creates/rotates `platform_controller`, then exits.

## Platform Admin secret copy

Platform Admin never directly mounts the service-owned controller secret. Install a private UID/GID 1001 copy after the source secret is created:

```bash
sudo install \
  -o 1001 -g 1001 -m 0600 \
  /srv/infrastructure/databases/mongodb/secrets/controller_password \
  /srv/apps/platform-admin/secrets/mongo_controller_password
```

Platform Admin then connects privately to:

```text
mongodb://platform_controller:...@mongodb:27017/admin?authSource=admin&replicaSet=rs0
```

The root credential and replica keyfile are never mounted into Platform Admin.

The `/mongodb` manager supports managed database + user creation, password rotation, encrypted connection reveal, database/user deletion and database size reporting. Application users receive `readWrite` only on their own managed database.

## n8n

Both n8n main and worker join `mongo_net`. MongoDB nodes should use host `mongodb`, port `27017`, replica set `rs0`, and application credentials generated by `/mongodb`. Never use `root` or `platform_controller` in workflows.

## Backup and restore

Use a temporary MongoDB client on `mongo_net` or `docker exec` without exposing port 27017.

```bash
mongodump --uri='mongodb://USER:PASSWORD@mongodb:27017/DATABASE?authSource=DATABASE&replicaSet=rs0' --archive=backup.archive --gzip
```

Restore:

```bash
mongorestore --uri='mongodb://USER:PASSWORD@mongodb:27017/DATABASE?authSource=DATABASE&replicaSet=rs0' --archive=backup.archive --gzip
```

Perform an actual restore test before treating a backup workflow as production-ready.

## Security invariants

```text
27017 is not host-published.
authorization is enabled.
replica-set internal authentication uses a persistent keyfile.
root is bootstrap/emergency only.
platform_controller is management-only.
application users are scoped to their own database.
service secrets and Platform Admin secret copies remain outside Git.
Platform Admin stores generated app passwords encrypted in its credential vault.
```
