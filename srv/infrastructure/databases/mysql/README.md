# MySQL Production Service

Private-first MySQL infrastructure for the VSM host.

## Architecture

```text
Platform Admin / n8n / n8n-worker
          |
       mysql_net
          |
    platform-mysql
          |
       /var/lib/mysql
```

Port `3306` is not host-published. Same-VPS clients use `mysql:3306`.

## Runtime layout

```text
/srv/infrastructure/databases/mysql/
├── compose.yml
├── .env
├── data/
├── backups/
├── scripts/init-controller.sh
└── secrets/
    ├── root_password
    └── controller_password
```

## First deployment

```bash
cd /srv/infrastructure/databases/mysql
mkdir -p data backups secrets
[ -f .env ] || cp .env.example .env
chmod 600 .env

[ -f secrets/root_password ] || openssl rand -hex 32 > secrets/root_password
[ -f secrets/controller_password ] || openssl rand -hex 32 > secrets/controller_password

docker network inspect mysql_net >/dev/null 2>&1 || docker network create mysql_net
```

The official image normally runs MySQL as UID/GID `999`. Verify that identity when changing image families. Both secret files must be readable during first-time database initialization:

```bash
sudo chown 999:999 secrets/root_password secrets/controller_password
sudo chmod 600 secrets/root_password secrets/controller_password
sudo chown -R 999:999 data
```

The tracked `init-controller.sh` is mounted into `/docker-entrypoint-initdb.d/` and runs only when `/var/lib/mysql` is initialized for the first time. It creates `platform_controller` through the local Unix socket. `MYSQL_ROOT_HOST=localhost` prevents creation of a long-lived remote root account.

Start:

```bash
docker compose config
docker compose pull
docker compose up -d
docker compose ps
docker logs platform-mysql --tail 100
```

There is no long-running or one-shot MySQL bootstrap sidecar. Once the data directory is initialized, controller bootstrap is not re-run on ordinary container restarts.

## Platform Admin secret copy

Platform Admin runs as UID/GID `1001` and does not directly mount the service-owned controller secret. After the MySQL controller secret exists, install a private app-local copy:

```bash
sudo install \
  -o 1001 -g 1001 -m 0600 \
  /srv/infrastructure/databases/mysql/secrets/controller_password \
  /srv/apps/platform-admin/secrets/mysql_controller_password
```

Platform Admin connects privately as `platform_controller` to `mysql:3306`. The MySQL root password is never mounted into Platform Admin.

The `/mysql` manager supports database + user creation, existing-user assignment, password rotation, encrypted connection reveal, database-only deletion, and database+user deletion. It refuses to delete a user that is still assigned to another managed database.

## n8n

Both n8n main and worker join `mysql_net`. Workflows should use an application-specific credential generated by `/mysql`, never `root` or `platform_controller`.

## Backup

Because `3306` is private, run logical backups with `docker exec` or a temporary client on `mysql_net`:

```bash
ROOT_PASSWORD="$(cat secrets/root_password)"
docker exec -e MYSQL_PWD="$ROOT_PASSWORD" platform-mysql \
  mysqldump -uroot --all-databases --single-transaction --routines --events \
  > backups/all.sql
unset ROOT_PASSWORD
```

## Security invariants

```text
3306 is not host-published.
root is localhost/bootstrap/emergency only.
platform_controller is management-only.
apps use dedicated users scoped to their database.
service secrets and Platform Admin secret copies remain outside Git.
Platform Admin stores generated app passwords encrypted in its credential vault.
```
