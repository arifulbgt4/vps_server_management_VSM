# MySQL Production Service

Private-first MySQL infrastructure for the VSM host.

## Architecture

```text
Platform Admin / n8n / n8n-worker
          |
       mysql_net
          |
    platform-mysql
          |
       /var/lib/mysql
```

The initial deployment does not publish `3306` to the host. Same-VPS clients use Docker DNS:

```text
mysql:3306
```

## Runtime layout

```text
/srv/infrastructure/databases/mysql/
├── compose.yml
├── .env
├── data/
├── backups/
├── scripts/init-controller.sh
└── secrets/
    ├── root_password
    └── controller_password
```

Create runtime state:

```bash
cd /srv/infrastructure/databases/mysql
mkdir -p data backups secrets
cp .env.example .env
chmod 600 .env
openssl rand -hex 32 > secrets/root_password
openssl rand -hex 32 > secrets/controller_password
sudo chown root:root secrets/root_password
sudo chmod 600 secrets/root_password
sudo chown 1001:1001 secrets/controller_password
sudo chmod 600 secrets/controller_password

docker network inspect mysql_net >/dev/null 2>&1 || docker network create mysql_net
```

`controller_password` is intentionally readable only by UID/GID 1001 because Platform Admin runs as UID/GID 1001 and mounts that file read-only. The one-shot bootstrap container runs with sufficient privilege to read it. The root password is never mounted into Platform Admin.

The MySQL image owns `/var/lib/mysql`. On the current official image this is normally UID/GID 999; verify the image before changing ownership on a new major release.

```bash
sudo chown -R 999:999 data
```

Start:

```bash
docker compose config
docker compose pull
docker compose up -d
docker compose ps
docker logs platform-mysql --tail 100
docker logs platform-mysql-init --tail 100
```

The one-shot `platform-mysql-init` container creates or rotates `platform_controller`. Applications must never use `root` or `platform_controller`; Platform Admin creates dedicated per-database users.

## Platform Admin

Platform Admin connects privately with:

```text
host=mysql
port=3306
user=platform_controller
```

It mounts only `controller_password`; the MySQL root password is not exposed to Platform Admin.

The `/mysql` manager supports database + user creation, existing-user assignment, password rotation, connection reveal from the encrypted credential vault, and database/user deletion.

## n8n

Attach both n8n main and worker to `mysql_net`. MySQL nodes should use host `mysql`, port `3306`, and an application-specific database credential generated by Platform Admin.

## Backup

Because 3306 is private, run logical backups from a client on `mysql_net` or with `docker exec` rather than publishing the port. Example from inside the database container:

```bash
ROOT_PASSWORD="$(cat secrets/root_password)"
docker exec -e MYSQL_PWD="$ROOT_PASSWORD" platform-mysql \
  mysqldump -uroot --all-databases --single-transaction --routines --events \
  > backups/all.sql
unset ROOT_PASSWORD
```

## Security invariants

```text
3306 is not host-published.
root is bootstrap/emergency only.
platform_controller is management-only.
apps use dedicated users scoped to their database.
controller/root passwords never enter Git.
Platform Admin stores generated app passwords encrypted in its credential vault.
```
